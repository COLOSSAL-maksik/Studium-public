# Настройки и резервная копия

«Настройки» внизу боковой панели содержат светлую и тёмную тему, диагностические пути и резервное копирование. Тема сохраняется при перезапуске. Учебные периоды управляются через верхний список периода.

Столбцы обычных таблиц можно менять мышью. Ширины сохраняются в локальных настройках для таблиц с соответствующими заголовками. Широкие таблицы прокручиваются горизонтально.

## Создать резервную копию

Нажмите **«Создать резервную копию…»** и выберите ZIP через диалог сохранения. Выберите обычную папку вне Git и каталога данных Studium, без символических ссылок и junctions. Работающее приложение получает согласованный снимок SQLite, включая данные WAL, и сохраняет все управляемые вложения, в том числе архивные. Простое копирование работающего `studium.sqlite` небезопасно.

ZIP сначала создаётся во временном файле, проверяется и только после успеха появляется по выбранному пути. Предыдущая копия при ошибке сохраняется. Прогресс виден в настройках; **«Отменить операцию»** безопасно останавливает работу и убирает временные файлы. Отмена файлового диалога ничего не записывает.

Если Studium сообщает о незавершённом импорте, перезапустите приложение для штатного восстановления файловой операции и повторите создание копии. Отсутствующее или повреждённое вложение не пропускается молча: сначала разберитесь с причиной ошибки.

## Проверить архив

Нажмите **«Проверить резервную копию…»** и выберите ZIP. Эта операция не восстанавливает данные и не меняет активное хранилище. Проверяются структура архива, версия, размеры, SHA-256, целостность SQLite, связи и наличие всех управляемых файлов. Результат показывает дату UTC, версию Studium и схемы, количество вложений и общий размер.

## Восстановить в отдельный каталог

Нажмите **«Восстановить в отдельный каталог…»** и выберите архив. Откроется предпросмотр с результатом проверки и предупреждениями. Если архив повреждён или несовместим, кнопка восстановления недоступна. Для проверенного архива выберите **отдельный пустой каталог** вне Git и активного хранилища.

Studium проверит архив повторно, восстановит данные во временную staging-папку и опубликует новый каталог только после полной проверки. Непустой каталог не перезаписывается. Текущая база и файлы сохраняются; приложение продолжает работать с ними. Автоматическое восстановление поверх текущей активной базы и автоматическое переключение намеренно не реализованы.

Отдельное восстановленное хранилище можно открыть после закрытия Studium через существующий параметр запуска `--data-dir`, например `Studium.exe --data-dir "D:\Studium-restored"`. Выберите именно опубликованный каталог. Настройки темы и ширины таблиц, миниатюры, кэш и логи в ZIP не входят.

## Конфиденциальность и отличие от экспорта

**ZIP содержит конфиденциальные данные и содержимое вложений. Он не зашифрован.** Храните копию в безопасном месте и передавайте только доверенным людям. Проверка SHA-256 обнаруживает повреждение; она не доказывает, кто создал архив. Не открывайте копии из недоверенных источников. Облачной отправки и сетевой синхронизации нет.

CSV и PDF из раздела «Отчёты» — документы для просмотра и передачи выбранных сведений. Они не содержат полную историю БД и bytes вложений, поэтому не заменяют резервную копию и не используются для восстановления.

**«Проверить состояние хранилища»** показывает каталог данных, версию схемы, размер согласованного снимка БД, число и размер управляемых файлов, состояние целостности и доступное место. Диагностика не удаляет и не исправляет записи. ФИО и содержимое файлов в диагностике не отображаются.

Portable-программа в dist и пользовательские данные — разные каталоги. Справка работает без интернета.

Обычный каталог данных — `%LOCALAPPDATA%\Studium`. База, файлы и миниатюры находятся вне папки исходного кода. Папку внутри Git-репозитория нельзя выбрать даже через `--data-dir`; для отдельной демонстрации укажите новый каталог вне репозитория. Передавайте другим людям только проверенные исходники, без каталога данных и резервных копий.
