## Пользовательский сценарий

1. Открыть «Дисциплины», создать дисциплину; период, группы и студенты не нужны.
2. В дисциплине открыть «Учебные программы» → «Создать учебную программу».
   На пустом профиле также доступен «Импортировать программу».
3. Заполнить паспорт: название, редакцию, необязательный учебный год, описание,
   несколько направлений. Каждая строка направления: `код — название` либо код.
4. В «Годовом плане» создать семестры и модули. Два начальных семестра —
   редактируемая заготовка; занятия и модули автоматически не добавляются.
   Дерево слева выбирает модуль, справа — занятия. Доступны массовое добавление,
   изменение, выбор/создание тем, копирование фрагмента, перемещение и удаление.
   При копировании модуля нужно выбрать свободные границы недель.
5. Заполнить знания, умения, компетенции и предварительную подготовку.
   Связи результатов с темами, навыками, модулями и работами необязательны.
   Предшествующая дисциплина может отсутствовать в местном справочнике.
6. В «Объёме дисциплины» проверить часы по видам, семестрам и за год.
   Лекции/семинары/лабораторные считаются по занятиям. Для других видов
   строка модуля описывает его нагрузку; строка без модуля — **остаток семестра
   вне модулей**, а не повторный итог модулей. Норматив вводится отдельно.
7. В «Баллах и заданиях» добавить предусмотренные работы и правила, при
   необходимости выбрать библиотечный шаблон. Каждая строка — одна работа;
   количество вычисляется из строк. Бюджеты категорий/модуля показывают
   распределение и остаток. Годовой максимум не ограничен числом 100.
   Можно явно отказаться от балльной системы. Дробный ввод использует прежнюю
   настройку приложения; минимум не является проходным порогом.
8. Выбрать материалы/литературу и добавить документы. «Сохранить черновик»
   позволяет продолжить после перезапуска. «Проверить заполнение» сообщает
   недостающее. Ненужные пустые разделы явно отмечаются «Не предусмотрено».
9. «Подготовить версию» проверяет полноту и атомарно создаёт immutable снимок.
   После этого окно работает в режиме просмотра. Новая редакция и независимая
   копия создают отдельный черновик. Группы продолжают использовать прежнюю версию.
10. «Экспортировать» создаёт `.studium-program`: можно включить все показанные
    файлы либо явно исключить их. Импорт сначала показывает preview и даёт
    выбрать дисциплину или создать новую; до подтверждения рабочие данные не пишутся.
11. В «Использовании / версиях» применить готовую версию к существующей группе,
    явно выбрать семестр курса и открыть её рабочий план. При переназначении
    используется прежний preview/confirmation/CAS с сохранением фактов.
12. В рабочем плане занятия показывают исходную и текущую неделю и темы.
    Перенос требует причины. Можно связать уже записанное фактическое занятие;
    фактические темы/дата остаются в прежнем окне занятия. Связь сама не создаёт
    занятия, посещаемость, выдачу работы, попытку или оценку.

Уход с изменениями предлагает «Сохранить черновик / Не сохранять / Остаться».
Ошибка или stale revision сохраняет введённый текст. Импорт/экспорт/копирование
документов используют BackgroundCall; Qt widgets читаются/меняются в GUI thread,
каждый application вызов открывает собственные короткие DB sessions.

## Модель и совместимость

Переиспользованы CourseProgram, immutable ProgramVersion, Direction /
ProgramDirection, VersionReference, SemesterPlan, PlanModule, PlannedWork,
PlanContentSource, PlanHistory, каталоги Topic/Skill/WorkDefinition/Problem,
семейства вариантов, точные cents, файлы и durable import journal, backup,
FormDialog, TopicTreePicker, BackgroundCall и существующий router/style.
Связанные прежние требования: ST-QA-002/003/006/010/011/013/021/023/030.
Пакет ST-QA-001–030 не начинается заново; его принятие сохраняется.

Новая additive `0013_annual_program` после v12 добавляет три таблицы:

| Таблица | Смысл |
|---|---|
| program_drafts | Редактируемый полный content JSON, CourseProgram, nullable base_version_id, обычный CAS revision |
| program_imports | Неизменяемые происхождение и fingerprint импортированной редакции, конкретная версия |
| plan_lessons | Независимые baseline/current JSON занятия плана, source key и версия, nullable связь с фактическим Lesson |

JSON `annual.schema_version=1` — единственный источник годовой структуры.
Порядок задаётся массивами; UUID keys семестров/модулей/занятий/работ устойчивы
при перестановках. Совместимые top-level modules/works строятся при публикации
как проекция для существующего механизма планов/выдачи, отдельно не редактируются.
Черновик не является ProgramVersion. Публикация не меняет прежние версии.
Тексты и зависимости уже сохранённых библиотечных источников сохраняются.
«Обновить библиотечные источники» явно выбирает текущее содержание для новой
редакции; прежняя V1 и планы не переписываются. Неизвестные локальные совместимые
поля/sections проходят через редактор без пересборки всего JSON по колонкам.

Ограничения связей, циклы, отрицательные/неточные числа проверяются и у черновика.
Полнота, положительные часы/темы готового занятия и превышение бюджета отдельно
проверяются при публикации. Часы — Decimal с точностью до 0,01 академического
часа; float, exponent, NaN и скрытое округление не принимаются. Норматив NULL
означает «не указано». Валидация, расчёты и DTO находятся вне обработчиков GUI.

v1–v12 Python/SQL payloads не меняются; backfill выдуманных часов, компетенций или
семестров отсутствует. Новые SQL guards сохраняют source/baseline занятия,
связь с исходным модулем/версией, scope группы и однонаправленную привязку факта.
Прежние frozen Topic/Skill/content guards остаются. Три новых таблицы автоматически
входят в строгий schema fingerprint и полный backup; SCHEMA_REVISION обновлён.
Старые ZIP backup по-прежнему требуют соответствующий прежний release и upgrade
отдельного восстановленного профиля, без подмены версии manifest.

Старые WorkProgram доступны через существующий compatibility mapping. Если
номер семестра неизвестен, дерево и список прежних работ показывают это явно.
В новом черновике старые модули нужно сопоставить с явно созданным семестром.
Утраченный pre-v11 снимок задачи не восстанавливается как исторический V1:
для новой редакции требуется явное обновление библиотечных источников.

## Формат обмена

Первая версия собственного формата; ранее поддерживаемых версий этого формата
нет. Unknown/future version отклоняется до записи. Это не SQLite backup,
не Word/PDF распознаватель и не исполняемый файл.

Контейнер ZIP `.studium-program` содержит:

- `manifest.json`: format=`studium-program`, integer version=1, origin
  `urn:uuid:<переносимая редакция>`, SHA-256 UTF-8 program.json, список файлов
  (portable id, оригинальное имя, размер, SHA-256), число исключённых файлов;
- `program.json`: паспорт дисциплины и whitelist структурированного содержания:
  annual, снимки тем/их родителей/навыков, связи тем и навыков, определения работ,
  зависимости, frozen effective задачи/семейства/варианты, structured answers и
  встроенные answer template schemas, материалы/литература и выбранные file links;
- `files/<portable UUID>`: точные выбранные байты. Original filenames не являются
  путями извлечения; каждый файл staging получает отдельный ID-каталог.

Локальные UUID заменяются portable IDs, а при импорте новым комплектом локальных
ID; все внутренние ссылки и словарные ключи переназначаются. Название не служит
идентичностью. Темы/шаблоны импортируются отдельно и в выбранную дисциплину.
Направления сопоставляются по прежнему normalized code; значимые различия имени
показываются в preview. Местный справочник не перезаписывается, входящее имя
сохраняется в паспорте версии. Повтор определяется парой origin + fingerprint
(program JSON и дескрипторы файлов с hashes). Можно открыть существующую редакцию
или явно создать независимую копию. Другая редакция не переключает группу.

Переносятся только известные учебные поля. Произвольные extension JSON,
локальные source paths/storage keys, настройки/credentials, студенты, группы,
посещаемость, оценки, попытки, сообщения и расписание группы не входят в allowlist.
Неизвестные локальные расширения остаются в исходной программе. Экспорт без
файлов очищает все file references и сообщает число исключений; структура и
тексты остаются полноценными. Экспорт не публикует материалы в GitHub.

Лимиты: 1026 ZIP entries, 256 МиБ total, 64 МиБ/вложение, 8 МиБ program JSON,
1 МиБ manifest/central directory, compression ratio ≤200. До ZipFile ограничен
central directory, проверены actual count и bounds; отвергаются traversal,
absolute/backslash/duplicate/case aliases, symlink/special/reparse entries,
encryption, неподдерживаемое сжатие и duplicate JSON keys. CRC, размеры, hashes,
ссылки и иерархия проверяются полностью. Preview read-only; commit повторно
проверяет source hash и staging. Экспорт пишет temporary + fsync + verify + atomic
replace, с защитой рабочей БД и managed files от замены.

Импорт использует SQL transaction внутри прежнего FileStorage.import_files.
Новые файлы публикуются до DB commit под durable journal; поздний отказ удаляет
весь новый набор. После аварийного завершения startup reconciliation сохраняет
байты с committed FileAsset и убирает незакоммиченные originals/markers. Видимой
полупрограммы SQL commit не оставляет. Recovery проверяется воспроизведением
остаточных markers по обе стороны commit; аппаратный power-loss не симулировался.
